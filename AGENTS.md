## Simulator & Device Testing Rules
- Every UI/keyboard change MUST be tested on **both iPad and iPhone** (iPadOS 26/27 + iOS 27).
- Check connected physical devices first (`xcrun devicectl list devices`): **iPad Air 3rd generation** (`<IPAD_DEVICE_UDID>`) and **iPhone 15 Pro** (`<IPHONE_DEVICE_UDID>`).
- When testing on connected physical devices (via USB or Wi-Fi DeviceHub), notify the user in chat that physical device testing is starting and proceed immediately without blocking on confirmation.
- **Mandatory Parallel Execution Across Physical Devices & Simulator**: Connected physical devices and the already-booted simulator consume zero extra simulator disk space. Automated installations (`xcrun devicectl device install/process launch`) and test runs (`xcodebuild test-without-building` with separate `-resultBundlePath` paths) MUST ALWAYS be launched **in parallel simultaneously** across all connected physical devices and the active simulator — never sequentially one after another — so results from all devices are collected at the same time.
- If a physical device (e.g. **iPhone 15 Pro**) is offline/unavailable, you MUST test that form factor on an iOS 27 simulator (`xcrun simctl`):
  - Check free disk space (`df -h /`) first.
  - If sufficient disk space is available, create/boot the missing approved simulator (**iPhone 15 Pro** / **iPhone 16 Pro** on iOS 27 or **iPad (A16)** on iPadOS 27) and test in parallel.
  - If disk space is tight (< 10 GB free), complete all tests, screenshots, and video capture on the active simulator first, delete that simulator (`xcrun simctl delete <udid>`) to reclaim space, and then create and test on the other form-factor simulator so both iPad and iPhone are thoroughly verified.
- Never pass `CODE_SIGNING_ALLOWED=NO` when building for Simulator (`xcodebuild`); Xcode's default ad-hoc signing with `.xcent` entitlements is required so `QTatar.app` and `Keyboard.appex` can share `UserDefaults(suiteName: "group.crh.key.keyboardplus")`.
- **Capacity-Aware Maximum Parallelism & Visual Proof**: Use the Mac's available CPU/RAM capacity to the maximum for parallel investigation, building, and testing while actively monitoring system load (`sysctl vm.loadavg`, `memory_pressure`) so concurrent tasks never conflict or freeze the machine. Every completed feature and fix MUST be verified and backed by visual evidence (screenshots or video recordings) in the final report.
- **Parallel Implementation + Continuous QA & Trace Subagent Pipeline**: Run a dedicated **Continuous QA Tester & Hang/Performance Trace Auditor** subagent in parallel alongside the **Implementation Engineer** subagent so completed sub-tasks are continuously benchmarked (`< 16.6 ms` frame budget, `< 100 ms` hang threshold, Unified Log / MetricKit / `.ips` audit) while implementation of subsequent tasks continues.

## Keyboard UI & Task Tracking Rules
- Interactive toolbar slots (such as the 3 autocomplete suggestion buttons in `Autocomplete+NativeToolbarStyle.swift`) MUST always apply `.frame(maxWidth: .infinity, maxHeight: .infinity).contentShape(Rectangle())` inside the `Button` label so the entire slot area responds to taps, not just the text glyph.
- Daily/motivational phrases in the keyboard top bar MUST be displayed as complete, self-contained sentences without ellipsis truncation (`...`); tapping them MUST only append parenthetical info `(...)` when attributing an actual author or folk wisdom/proverb (never append category labels like `(Sağlıqlaşuv)` or `(Selâmlaşuv)`), and MUST NEVER count toward user typing statistics.
- Typing statistics MUST distinguish words typed manually letter-by-letter from words completed via the 3 autocomplete suggestions (suggestions do not inflate manual typing speed), include speed/volume progression levels based on realistic typing norms, and provide a confirmation dialog before resetting statistics.
- Autocorrection and Orthography rules MUST comply with the official 2024/2025 Crimean Tatar Orthography (ДЕСС № 1722/04-03/25), support immediate Backspace (`⌫`) undo of the last space-committed autocorrection (and single-tap `⌫` full-word deletion of a just-swiped word), support hyphenated compound words (`§ 63`, e.g. `gece-kündüz`, `alış-veriş`), merge trailing question particles `-mı/-mi` (`§ 67`, e.g. `yaptıñ mı -> yaptıñmı`), auto-capitalize unambiguous Crimean Tatar toponyms/proper nouns (`Qırım`, `Aqmescit`, `Bağçasaray`, `Çonğar`, `Or Qapı`), and offer the Ukrainian-adapted Cyrillic layout (`"Українська розкладка"`, `ФІВА`) when Cyrillic keyboard is enabled and the app or iOS system language is Ukrainian (`uk`):
  - Ukrainian `ФІВА` mapping: replace Ukrainian `е -> э` (`e`, so `дембель -> dembel`, `ервін -> ervin`, `мен -> men`, `сен -> sen`), `є -> е` (`ye` initially/after vowel/separator, `e` after consonant, so `єр -> yer`, `єшіль / єшиль -> yeşil`, `аєт -> ayet`), `і -> i`, `и -> ı` (and `i` after sibilants `ж, ч, ш, щ` in soft words), `ґ -> g`, `г -> ğ`, and smart apostrophe `ʼ` (`U+02BC` at Row 0, Col 11): outputs literal `ʼ` immediately on the first tap when not after a consonant (after vowels, at word start, or after space/punctuation), forms `кʼ -> q`, `нʼ -> ñ`, `гʼ -> ğ`, acts as hard-sign separator after other consonants (`пʼєр / пʼер -> pyer`), and outputs literal `ʼ` on double tap (`ʼʼ`).
  - `HomeView.swift` Ukrainian layout row: title `"Українська розкладка"` (`"Ukraina tizilişi"` / `"Ukrainian layout"`), concise 4-item subtitle `ґ → g · г → ğ · кʼ → q · нʼ → ñ`, keycap badge `Кʼ` with blue-yellow gradient when ON and gray (`Color(.systemGray3)`) when OFF.
  - Spacebar label (`SpaceBarLabel.swift`): full title uses Title Case (`"Qırımtatarca"`, `"Къырымтатарджа"`, `"Кʼиримтатарджа"`) and collapses after 3 seconds into a **2-character uppercase code** in the bottom-right corner (`"QT"`, `"КЪ"`, `"Кʼ"` — never 3-character `"КЪТ"`).
- **Swipe-to-Type (`QırımKey Swipe v2`)**:
  - Only active on iPhone (`deviceType == .phone`) and iPad Floating (`isKeyboardFloating == true`).
  - Must pass continuous `[TrailSample]` `(x, y, t)` and live `keyFrames` from `endSwipe()`, weight turning-angle anchors ($\Delta\theta \ge 22^\circ$) vs collinear transit keys, strip Row-0 right-flank transit keys (`е, н, г, ш, щ, з, х`) before/after `ъ`/`ʼ` on `ФЫВА`/`ФІВА`, score `i == 0` by physical start-key distance on the 12-column layout without `k <-> q` / `s <-> ş` prefix expansion, and use separate SQL candidate pools for exact (`320`) vs neighbor (`140`) ending characters.
- **Dark/Light Theme Sync & `HomeView` Polish**:
  - `KeyboardViewController` and `DemoStyleProvider` must synchronize App Group preferences (`CFPreferencesAppSynchronize`), clear stale sandbox theme overrides when the host app is inactive, and pass `.environment(\.colorScheme, ...)` to `SystemKeyboard` so Spotlight and Dark Mode hosts never render light keys or dark text on a dark background.
  - `TaraqTamgaLogoBadge` must render the real app icon (`UIImage(named: "logo")`) and adapt to Dark Mode; `ScrollView` in `HomeView.swift` must sit directly inside `NavigationStack` (without an outer `GeometryReader`) to preserve native Liquid Glass scroll-edge blur; and the Cyrillic status pill must show a static `✓ Додано` badge without `>` when already added in iOS Settings.
- Peer UI elements of the same hierarchy level (such as settings row titles or subtitles in `HomeView.swift`) MUST render at an identical effective font size without per-row `.minimumScaleFactor` shrinkage differences.
- Default interface language MUST be Crimean Tatar (`crh`), managed in-app without exposing a redundant language picker in iOS System Settings.
- Standard iOS/iPadOS keyboard features MUST strictly match official system behavior without inventing redundant settings in `HomeView.swift`: iPad Split Keyboard MUST only be active on iPad models supported by UIKit (`UIKeyboardDeviceSupportsSplit()`), controlled via the bottom-right `⌄⌨` vertical callout menu and pinch gesture; `Docked ↔ Floating` transitions MUST keep the floating platter clamped within `UIScreen.main.bounds`; and all `Settings → General → Keyboards` traits (`UITextDocumentProxy`, `UILexicon`, `playInputClick()`, Smart Punctuation, Show Maths Results) MUST be respected.
- **Reverse-Chronological Journal & $\le 20$-Minute Sub-Tasks in `task_tracker.md`**:
  - Maintain `task_tracker.md` as a reverse-chronological journal (newest phases and sub-tasks at the top, older completed phases at the bottom).
  - Break every task into granular sub-tasks of **$\le 20$ minutes** each, run a recurring 20-minute timer/cron checkpoint during multi-agent execution, and update `task_tracker.md` at least every 20 minutes.
  - Before modifying existing UI or behavior, check whether it was previously requested by the user and working as intended — never regress approved behavior.
  - Mark `[x]` for completed items, `[/]` **only** for the exact item(s) actively being executed at that moment, and `[ ]` for queued items.
